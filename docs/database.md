# LABGUARD Database Architecture & Schema

LABGUARD utilizes a fully normalized PostgreSQL schema hosted on **Supabase** (or any standard PostgreSQL 15+ instance). All entities use `UUID` primary keys generated by `gen_random_uuid()`.

---

## 1. Schema Overview: 21 Core Tables

1. **`roles`**: Strictly four records (`ADMIN`, `FACULTY`, `LAB_ASSISTANT`, `STUDENT`).
2. **`users`**: Central credentials table storing email, bcrypt hash (`password_hash`), full name, phone, and active status.
3. **`students`**: Student academic attributes: `student_id` (e.g. STU-2023-0101), department, section, semester.
4. **`faculty`**: Faculty employee profile: `employee_id` (e.g. FAC-CSE-014), department, designation.
5. **`lab_assistants`**: Technical staff profile: `employee_id`, department, shift (`MORNING`, `EVENING`, `GENERAL`).
6. **`labs`**: Dynamic laboratory entities: `code` (`LAB-01` to `LAB-07`), name, room, description, status, pc_count.
7. **`computers`**: Workstations: `lab_id`, `pc_code` (`PC-001`, `PC-017`), hostname, IP address, MAC address, status (`AVAILABLE`, `OCCUPIED`, `MAINTENANCE`, `OFFLINE`), is_online, last_heartbeat.
8. **`equipment`**: Peripherals: `asset_id` (`KB-017`, `MS-017`), type (`KEYBOARD`, `MOUSE`, `MONITOR`), brand, model, serial_number, status, `qr_code_data`.
9. **`computer_equipment`**: Active mapping between computers and peripherals with slot types (`KEYBOARD`, `MOUSE`).
10. **`user_lab_assignments`**: **RBAC Cornerstone**:
    - `id`, `user_id`, `lab_id`, `assignment_type` (`FACULTY`, `LAB_ASSISTANT`), `assigned_from`, `assigned_to`, `status`.
    - Enables scalable, dynamic multi-lab access control.
11. **`subjects`**: Course catalog (e.g. CS301 - Java Enterprise Programming).
12. **`class_sessions`**: Scheduled/active classes in a lab with expected students count.
13. **`class_students`**: Class roster and attendance tracking.
14. **`sessions`**: Workstation usage tracking: `user_id`, `role`, `lab_id`, `computer_id`, `start_time`, `end_time`, `status`, `duration_minutes`.
15. **`hardware_events`**: Peripheral connect/disconnect stream with neutral wording.
16. **`issues`**: Problem ticket lifecycle (`OPEN`, `VERIFIED`, `INVESTIGATING`, `MAINTENANCE`, `RESOLVED`, `REJECTED`).
17. **`issue_events`**: Incident timeline entries with comments, actions taken, and evidence URLs.
18. **`maintenance`**: Repair tasks with technician name, scheduled/completed dates, cost, and notes.
19. **`notifications`**: Role- and lab-scoped standardized alerts (`PC_OFFLINE`, `HARDWARE_DISCONNECTED`, etc.).
20. **`notification_preferences`**: Per-user alert preferences (hardware, issue, maintenance, session, system, email).
21. **`audit_logs`**: Immutable administrative action records (action, user, entity, entity_id, timestamp, metadata).
